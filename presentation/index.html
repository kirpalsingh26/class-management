The Problem

Challenges in Traditional Academic Record Keeping

1. Fragmented Tools

Colleges rely on disconnected channels: paper attendance registers, homework over WhatsApp groups, and study materials on open Google Drive links. Important deadlines get lost in message spam.

Result: Missed submissions and lost records

2. Manual Attendance Calculation

Faculty spend hours at the end of each semester manually summing present marks and calculating percentages. Human error leads to disputes during exam hall ticket clearance.

Result: Students unaware of attendance shortage (< 75%)

3. Zero Data Isolation

Public file links allow any student to access files meant for other sections. Furthermore, assignments submitted in group chats are visible to peers, violating academic integrity.

Result: Security leaks and plagiarism risks
Speaker Talking Points: "Slide 2 outlines why this project was needed. In our colleges, attendance is often kept in paper registers or scattered Excel sheets. Notes and homework are sent across informal WhatsApp groups where deadlines get buried. More importantly, students have zero real-time visibility into their attendance percentage until the end of the term, leading to shortages. Furthermore, open Google Drive links lack role-based boundaries. EduManage was engineered specifically to solve these 3 critical challenges."
System Objectives

Core Deliverables & Design Goals

A

Strict Role-Based Access Control (RBAC)

Establish two distinct, secured personas: Teacher (administer classes, mark attendance, post materials, grade submissions) and Student (view enrolled classes, monitor attendance %, download work, submit assignments).

Backend rule: Student requests to administrative endpoints return HTTP 403 Forbidden.
B

Multi-Class Roster Management

Enable faculty to create classes with unique subject codes, search registered students by name or roll number, and enroll them with one click.

Safety rule: Unenrolling a student removes class membership without deleting user account or other records.
C

Automated Attendance Engine

Fast daily attendance marking with idempotent upsert: re-saving a date updates records instead of creating duplicate rows.

Formula: Attendance % = (Present Classes / Total Classes Held) × 100 (Late tracked distinctly).
D

Protected Coursework & Submission Gateway

Distribute assignments, classwork, projects, and notes across targeted classes. 10MB validated uploads with protected file streaming.

Gateway rule: Downloads check token and class membership; public URLs are blocked.
Speaker Talking Points: "Here are our four principal project deliverables. We set out to provide strict role separation, scalable multi-class roster enrollment, an idempotent daily attendance engine with transparent percentage calculation, and a protected coursework module that eliminates unauthorized access to academic files."
System Architecture

3-Tier Full-Stack Architecture

Tier 1 Client

Presentation Layer

React 19 Single Page Application bundled with Vite.

  • Responsive Tailwind CSS v4 styling
  • Client-side Role Guards (React Router v7)
  • Axios interceptors with Bearer token injection
  • Instant UI feedback & visual progress meters
Runs in User Browser
Tier 2 Server

Application / API Layer

Node.js with Express.js REST API Architecture.

  • JWT Token verification middleware
  • Role-based route controllers (Teacher vs Student)
  • Multer file upload validation (MIME, size)
  • Protected file streaming gateway
Port 5001 Express REST API
Tier 3 Database

Data Persistence Layer

MongoDB NoSQL document database with Mongoose ODM.

  • 6 Normalized Collections with Mongoose schemas
  • Compound Unique Indexes (prevents duplicate attendance)
  • Referential integrity via ObjectId relations
  • Lean query projections & indexing
Port 27017 MongoDB Daemon
Speaker Talking Points: "This slide illustrates the 3-Tier Architecture. In Tier 1, React 19 handles user interaction and client routing. In Tier 2, Express handles business logic, JWT authentication, and file validation. In Tier 3, MongoDB stores our normalized collections. The key takeaway here is that static files are not hosted publicly; they must go through the Tier 2 gateway, which validates user permissions before streaming file bytes."
Tech Stack Justification

Why MERN Stack with Modern Tooling?

React 19 + Vite + Tailwind CSS

Sub-second development iterations and optimized production bundle.

  • • Instant HMR: Vite uses native ES modules, eliminating slow webpack rebuilds.
  • • Build Speed: Full frontend compiles in just 220 milliseconds.
  • • Tailwind CSS v4: Zero-runtime styling with fine-grained responsive control.

Node.js + Express.js

High-throughput asynchronous non-blocking event-driven API.

  • • Single Language Stack: JavaScript end-to-end simplifies mental model and maintenance.
  • • Middleware Pipeline: Modular authentication, CORS, body parsing, and route guards.
  • • RESTful Conventions: Predictable JSON responses with standard HTTP status codes.

MongoDB + Mongoose ODM

Document-oriented persistence with schema enforcement.

  • • JSON-Native: Classes and assignments fit naturally as structured documents.
  • • Compound Unique Indexing: Hard database guarantee against duplicate attendance records.
  • • Mongoose Validation: Strict type validation and referential population.

JWT + bcryptjs + Multer

Standard cryptographic and file safety libraries.

  • • Stateless Auth: JSON Web Tokens avoid server-side session memory overhead.
  • • Secure Salting: bcryptjs with 10 rounds protects passwords against rainbow tables.
  • • Multer Engine: Enforces 10MB file caps, MIME filters, and sanitized storage names.
Speaker Talking Points: "When examiners ask why we selected this stack: It gives us maximum developer velocity, asynchronous performance for handling student traffic spikes, and strict schema validation through Mongoose without needing cumbersome migrations."

Standardized Attendance Metrics

Attendance percentage is computed using a rigorous formula applied consistently across both faculty reports and student dashboards.

Attendance % = (Classes Attended / Total Classes Held) × 100
≥ 75%: Safe Attendance (Green Progress Meter)
60% - 74%: Warning Zone (Amber Meter)
< 60%: Shortage Alert (Red Meter)

  • • Optional Maximum Marks.
  • • Strict submission deadlines.

File Upload Validation

Multer middleware strictly validates incoming binary attachments before saving to disk.

  • • MIME filter: PDF, DOCX, PPTX, Images.

Security Architecture

Multi-Layered Security & Access Control

1. Authentication & Passwords

  • • bcryptjs Salt Rounds: 10 rounds of salt generation ensure high resistance against brute-force attacks.
  • • Stateless JWT: Signed tokens containing user ID and role, verified on every protected request.
  • • No Public Teacher Sign-up: Teacher accounts can only be seeded or created by administrators.

2. Dual-Layer Route Authorization

  • • Client-Side Guard: React Router `` checks user role before rendering views.
  • • Server-Side Enforcer: `requireRole('teacher')` blocks unauthorized API calls (HTTP 403).
  • • Tamper-Proof: Bypassing client UI yields zero access because the backend enforces authorization.

3. Class Boundary Isolation

  • • Query Scoping: Students can only retrieve data for classes where their ID is in `enrolledStudents`.
  • • Coursework Filtering: Work and announcements are filtered by class membership.
  • • Teacher Scoping: Teachers only modify their own assigned classes.

4. Upload & Injection Defense

  • • Safe Filenames: Multer stores files using random cryptographic hashes to prevent path traversal.
  • • Mongoose Type Casting: Mitigates classic NoSQL injection vulnerabilities.
  • • CORS Filtering: Disallows unapproved origin domains from sending authenticated requests.
Speaker Talking Points: "Security is critical for any college project defense. Our backend has dual-layer defense: even if someone bypasses the frontend and uses cURL or Postman to invoke an administrative endpoint, the backend middleware inspects the JWT payload and immediately responds with 403 Forbidden."
